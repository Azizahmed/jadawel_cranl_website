# Presentations

Apply these rules to PowerPoint, Google Slides-targeted decks, pitches, product demos, and speaker presentations.

## Art direction

- Default to a 16:9 canvas unless the user or template specifies otherwise.
- Use blue or ink for decisive section dividers and light backgrounds for content-heavy slides.
- Place one dominant message, diagram, product view, or data story on each slide.
- Use the full composite lockup prominently on the cover and closing slide. Use a restrained footer signature only when helpful; the logo does not need to appear on every slide.
- Reuse modular squares, the vertical bar, open space, and the diamond to create rhythm across sections without detaching the five-square logo symbol.

## Type and bilingual behavior

Use Thmanyah Sans weights consistently. Keep Arabic text in logical order with native RTL paragraph settings. Keep English paragraphs in separate LTR boxes. Separate mixed metadata into stable runs or boxes when dates, units, or version numbers reorder between applications.

## Charts and product visuals

Use blue for the selected series or key value. Use light blue for comparison values and semantic state colors only for meaning. Label axes, units, and sources. Product screenshots should be legible at presentation distance and should not be distorted.

## Deliverables and verification

Provide an editable PPTX when requested and a PDF preview when practical. Verify slide count, dimensions, package integrity, font availability, Arabic direction, and visible layout. Render and inspect every final slide individually. State whether Microsoft PowerPoint, Google Slides, LibreOffice, or only a renderer was used for target-application QA.

The packaged reference includes two PowerPoint variants. `Jadawel_Visual_Identity_Guidelines_AR_v1.1.pptx` is visual-safe: every page is a high-resolution slide image, so Arabic cannot reverse in viewers with incomplete RTL support. `Jadawel_Visual_Identity_Guidelines_AR_v1.1_editable.pptx` preserves editable logical-order Arabic and native RTL properties. Use the visual-safe file for dependable viewing and the editable file only when modification is necessary.
